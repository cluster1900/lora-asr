# 00 文档治理

最后更新：2026-06-07

## 背景

本项目会涉及数据、训练、推理、router、评测、Colab notebook 和实验记录。如果没有文档先行，很容易出现代码先乱跑、指标不可复现、结果无法比较的问题。

## 目标

建立一套轻量但严格的文档工作流，保证每次功能开发都有背景、范围、设计、测试和验收标准。

## 范围

本步骤只处理文档结构和协作规范，不实现训练或推理代码。

## 需要维护的文档类型

- 架构文档：描述系统为什么这样设计、模块目的、输入输出、依赖关系、达成标准。
- 开发文档：描述功能拆分、文件位置、接口约定、开发步骤。
- 数据文档：描述数据来源、格式、增强、切分、质量检查。
- 训练文档：描述训练目标、配置、资源、checkpoint、停止条件。
- 测试文档：描述测试集、指标、命令、通过标准、失败分析。
- 进度文档：记录已完成、进行中、下一步、阻塞和实验结论。
- 风险文档：记录技术风险、决策原因、替代方案和回滚条件。

## 执行步骤

1. 检查 `AGENTS.md` 是否包含文档先行、测试标准和验收标准。
2. 检查 `docs/qwen3-asr/` 是否包含架构、开发、数据、训练、测试、进度、风险文档。
3. 为每个新增功能建立 roadmap 或 feature 文档。
4. 文档中必须写清楚本功能是否影响架构、数据、训练、推理或评测。
5. 每次实现完成后更新进度文档。

## 文档质量标准

每个功能文档至少包含：

- 背景：为什么做。
- 目标：做到什么程度。
- 范围：做什么、不做什么。
- 输入输出：数据、配置、文件。
- 执行步骤：按顺序列出。
- 测试标准：如何验证。
- 验收标准：什么叫完成。
- 风险：可能失败在哪里。

## 测试标准

- 新增文档能从 `roadmap/README.md` 找到。
- 文档之间链接无明显断链。
- 每个步骤都有测试标准和验收标准。
- 主 README 能指向路线图。

## 验收标准

- `AGENTS.md`、主 README、进度文档和 roadmap 索引都已更新。
- 后续开发可以直接按 roadmap 步骤执行。
- 没有“只写目标，没有验收”的文档。

## 风险

- 文档过长导致没人维护。控制方式：路线图文档写执行要点，实验细节写到具体功能文档或结果文档。
- 文档与实现脱节。控制方式：每次功能完成必须更新进度和结果。
